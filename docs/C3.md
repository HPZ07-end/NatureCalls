# 《借过！我很急！》游戏设计案 V0.3

> 来源：[C3.pdf](C3.pdf)，共 5 页。本文件按原文转换为 Markdown，合并跨页段落与表格，保留原有方案、阶段和待定事项；不代表这些机制已经实现或验证。

**最近修改：** 10.15

**类型：** 多人实时合作派对游戏

## 1. 玩家与场景：谁玩、在哪里玩、玩多久

| 项目 | 当前方案 |
| --- | --- |
| 人数 | 待定；首版建议按 **4 人**设计 |
| 时长 | **10 分钟**，实时进行 |
| 游玩形式 | 多人同场协作；本地同屏或线上等具体载体待定 |
| 场景 | 一间设施经常出现故障的公共厕所；首版只制作一张地图 |
| 视觉 | 卡通角色、状态提示、夸张动画与音效；避免写实排泄表现 |

玩家既是厕所的使用者，也是临时维护者。每个人的如厕急迫值不断增长；隔间、门锁、供水、排水和物资又可能出现问题。个人完成如厕后，公共设施仍可能留下污物或故障。

地图包括若干厕所隔间及马桶／蹲厕、隔间门、公共区域的小便池、水闸、卷纸、水池、清洁工具箱和连接各隔间的公共排水系统。隔间数量、地图尺寸与初始故障配置随人数测试确定。

| 设施 | 用途 | 可能发生的问题 |
| --- | --- | --- |
| 马桶／蹲厕 | 供玩家如厕与冲水 | 冲水失败、堵塞、溢出 |
| 隔间门 | 进入、离开与提供隐私 | 无法关闭或打开；详细规则留待后续 |
| 小便池 | 公共区域的如厕设施 | 漏水等具体规则待定 |
| 水闸及公共排水 | 调控冲水、连接各隔间 | 排水不畅、局部堵塞、整体倒灌 |
| 卷纸 | 可取用、移动与共享 | 用完、受潮、被别人占用 |
| 水池 | 提供清洁与手动冲水用水 | 暂无独立故障设计 |
| 工具箱 | 存放清洁与维修工具 | 工具被取走，其他玩家需寻找或等待 |

同一个卷纸设施在同一时间只能由一名玩家操作。首版不要求上表中的所有异常同时实现。

## 2. 目标与胜负：玩家为什么行动、怎么算赢

游戏有两项同时存在的目标：

- **个人目标：** 在自己的急迫值到达上限前找到设施并完成如厕，避免失控事故。
- **团队目标：** 在 10 分钟内共同维护厕所，避免公共清洁值触及失败阈值。

玩家必须在“先解决自己”与“先帮助大家善后”之间分配时间。自己已经上完厕所的人可以冲水、清扫或帮下一人开门，也可以离开并准备下一次如厕。

| 结果 | 当前判定 |
| --- | --- |
| 团队胜利 | 时间结束时，公共清洁值始终未触及失败阈值；首版暂以清洁值作为唯一公共失败条件 |
| 团队失败 | 公共清洁值触及失败阈值，全体立即失败 |
| 个人失控 | 带来短暂惩罚和新的污染；该玩家仍继续参与，不直接结束全局 |

**首版不设固定阵营、隐藏破坏者、个人排名或竞争得分。** 结算可以展示个人失控与贡献数据，但它们不决定谁赢。

公共清洁值会因未处理污物、堵塞溢出、地面积水、呕吐等下降；冲水与清扫可恢复清洁。清洁值初值、扣除量、恢复量及失败阈值均待测试。

## 3. 核心循环：玩家反复做什么

本游戏**实时进行**，不采用逐人轮流行动的回合制。

### 个人循环

**急迫值增长 → 判断剩余时间与可用设施 → 排队或求助 → 进入设施并完成如厕 → 急迫值归零 → 再次增长。**

每位玩家的急迫值独立增长，开局初始值随机。玩家能看到自己的数值与预计失控时间。完成如厕操作时，急迫值就清零并开始下一轮增长。**冲水、清洁和维修不构成“如厕完成”的前置条件。** 厕纸在如厕后的具体用途仍待确定。

### 公共循环

**使用设施 → 留下污物或增加排水负担 → 冲水、清洁、维修或暂时离开 → 环境改变 → 下一位玩家承受当前状态。**

两条循环同时运行。某人已经解决个人急迫，却可能留下不能马上供下一位使用的隔间；负责清理的人又可能因耽误时间而面临自己的失控风险。

### 失手与连锁

急迫值达到上限时，玩家发生卡通化失控：当前行动被打断，短暂无法正常操作，在所在位置留下需要清理的污物；急迫值随后重置到上限以下，玩家继续游戏。惩罚时长、污染量与重置值待测，须保证**故意失控不会比正常如厕更有利**。

恶心值是计划加入的第二层个人状态：脏污、堵塞溢出、倒灌、门意外打开或接触污染会增加恶心；不同玩家可有不同敏感度。达到上限则短暂呕吐、产生新污物，之后恶心值回到安全范围。远离污染、水池清洁等缓解方式待定。**建议在基础循环成立后再加入恶心值**，避免首版同时调试两套个人状态。

## 4. 行动与资源：玩家能做什么、付出什么

| 行动 | 效果 | 代价或限制 | 开发阶段 |
| --- | --- | --- | --- |
| 移动、排队、进入隔间 | 找到空闲且可用的设施 | 消耗时间；坑位有限 | 基础循环 |
| 如厕 | 解决当前个人需求 | 占用设施；可能留下待处理污物 | 基础循环 |
| 冲水、用水桶手动冲水 | 清理马桶污物 | 需要供水、排水能力或清水；可能堵塞溢出 | 先做简单冲水，强度差异后测 |
| 清扫 | 处理污物与积水、恢复公共清洁 | 消耗时间；工具可提高效率 | 基础清洁逐步加入 |
| 维修、疏通 | 恢复设施与排水能力 | 需要时间、工具或队友配合；细节待定 | 环境事故阶段 |
| 取纸、递纸、传工具 | 帮助别人善后或维修 | 同一资源被多人争用，需送到现场 | 合作玩法逐步加入 |
| 开关门、用万能钥匙 | 进入隔间或帮助被困者 | 门故障与钥匙规则待定 | 后续扩展 |
| 调节水闸 | 影响各隔间冲水和公共排水 | 对管道负担的作用待定 | 后续扩展 |

**水桶**可从水池取清水用于手动冲水，也可能装脏污；内容物应清晰区分，误用可能引发新污染。**拖把**用于清理地面污物和积水。**万能钥匙**用于打开故障隔间门。工具可传递，其持有人和到达时机影响分工。

尚未确定的关键资源规则包括：厕纸究竟用于哪种善后操作；不同冲水强度与故障概率、管道负担的关系；小便池的具体用途；是否设置多人同时操作的维修任务。此整理稿不把它们写成已验证机制。

## 5. 信息与互动：谁知道什么、如何合作

- **个人信息：** 玩家看到自己的急迫值与预计失控时间；加入恶心系统后，也看到个人恶心状态。
- **公共信息：** 玩家能够辨认隔间的占用、污染、故障情况，并看到公共清洁值。具体界面与信息精度待设计。
- **事故反馈：** 排水不畅应先有迹象，再发展为堵塞；冲水导致溢出时，要让玩家看懂原因和补救方式。

当前方案依靠**信息沟通与行动分工**产生互动：谁最急、哪间能用、工具在谁手上、谁先清理、谁先抢修。玩家可以口头约定“我帮你清理，你先进去”，但实际选择会受到自身急迫值影响。

例如，A 即将失控；B 刚完成如厕，隔间里留下污物；C 正在处理另一隔间的排水；D 拿着拖把。B 若马上冲水，排水不畅可能引发溢出；若等 C 疏通，A 可能来不及使用。D 也必须决定先清理 A 要用的隔间，还是先处理公共区域持续降低清洁值的污物。

本版**没有隐藏身份、假维修或固定“30% 隐藏损坏”规则**。故障可以有预兆和不完全信息，但玩家应能观察、沟通并采取行动，不靠盲猜决定胜负。

## 6. 事件与节奏：事故何时出现、高潮如何形成

以下时间分段是**体验节奏建议**，不是按表强制刷出故障：

| 时段 | 主要变化 | 预期体验 |
| --- | --- | --- |
| 约 0-2 分钟 | 初始急迫值不同，玩家熟悉坑位与物资分布 | 第一轮排队、借工具和求助 |
| 约 2-7 分钟 | 污物未及时处理，排水不畅、堵塞和积水逐渐叠加 | 协商“先上厕所还是先维护” |
| 约 7-10 分钟 | 遗留问题形成连锁，几名玩家可能同时急迫 | 集中抢修、清洁与让位，努力撑到结束 |

主要意外来自玩家使用设施后的环境变化，例如：**排水不畅出现提示 → 玩家继续冲水 → 堵塞或溢出 → 地面与卷纸受到污染 → 清洁值下降 → 清理者恶心上升 → 可能呕吐并增加清洁任务。**

随机故障可以改变局面，但应有可识别预兆、可理解原因和现场可执行的补救。停水、厕纸短缺、门锁失灵等可作为以后测试的事件；持续时间、触发概率及是否进入首版都尚未决定。随机事件不应直接宣告团队失败。

## 7. 结算与重开：怎么结束、下一局如何变化

时间结束且公共清洁值未触及失败阈值，展示**全体胜利**；清洁值触及阈值则立即展示**全体失败**。结算可记录每人的如厕次数、个人失控次数、清理量、维修次数、工具传递和帮助次数，以及关键事故链。**首版没有个人冠军**；这些数据用于回顾和试玩评估。

重开时使用同一张首版地图，随机调整初始急迫值、物资位置和少量设施初始状态，使相同规则产生不同的分工局面。额外地图与设施待首版验证后再制作。

### 首版原型范围

| 阶段 | 实现范围 | 验证目标 |
| --- | --- | --- |
| **一：基础循环** | 一张地图、多人移动交互、隔间占用、急迫值与失控、如厕后污物、简单冲水、公共清洁值 | 自然分工是否出现？倒计时能否带来压力？ |
| **二：环境事故** | 堵塞、溢出、公共排水、基础工具与物资传递、恶心及呕吐 | 事故是否看得懂、修得好？清理是否有趣？ |
| **三：按试玩结果扩展** | 门锁与万能钥匙、冲水强度、水闸调控、可移动与受潮卷纸、小便池、额外地图 | 哪些机制增强合作与笑点，又不使工作量失控？ |

### 待验证问题

1. **人数与坑位：** 4 人局需要几间隔间才能紧张而不频繁卡死？
2. **公共目标：** 玩家是否会主动清理，还是各自如厕也能撑满 10 分钟？终场是否需要附加可用设施条件？
3. **急迫值与失控：** 增长速度、事故重置值、短暂惩罚如何设置，才能防止故意失控获利？
4. **清洁值：** 污染如何扣分、是否持续恶化、清理如何恢复，才能避免反复按键？
5. **厕纸与冲水：** 厕纸在如厕完成后的作用是什么？强度、管道负担、故障和修复如何形成直观因果？
6. **恶心值：** 敏感度差异、恢复方式与呕吐连锁会增添乐趣，还是增加理解负担？
7. **可恢复性：** 每类故障是否都有补救路径？多人任务、随机故障与新设施应按什么顺序加入？

**当前设计目标：** 做出一局可玩的多人实时合作游戏。每个人不断解决自身急迫，同时共同处理如厕留下的环境问题，在持续变化的公共厕所里坚持 10 分钟。
