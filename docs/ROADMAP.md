## 待办：专用服务器按需建房（2026-11-19 记录，未开始）

现状：课程服务器上常驻一个房间（`naturecalls@8000`），地址即房间号，所有人进同一个房间，同时只能有一组玩家。

目标：有玩家要玩时才建房，每次给一个新的短房间号，没人后自动回收。

方案（待实施，规则部分需人类批准）：
1. 服务器上常驻一个 Python 房间分配器，经已开放的 TCP 8080 接收请求；建房时在 UDP 8001–8100 中找空闲端口启动一个游戏服务器进程，生成短房间号并记录「房间号 → 端口」。
2. 加入时输入房间号，客户端先向分配器查询端口再连接，玩家不需要知道 IP 和端口。
3. 房间空置一段时间（如 2 分钟）后结束进程并回收端口与房间号；按服务器资源（2 核、3.6 GB）限制同时房间数（约 3 个），满员时提示改用 Relay。
4. 分配器需要防滥用：每个 IP 的建房频率与房间总数上限。
5. 部署：分配器与其 systemd 服务纳入 `scripts/deploy_server.py`。

需要人类决定：大厅是新增「创建服务器房间」入口、把「创建房间」改为先选 Relay 或服务器，还是默认使用服务器建房（属于 GLOSSARY 中 Lobby 定义的变化）；常驻的 8000 房间是否保留为公共房间。分工：分配器、服务器与客户端逻辑交给 Codex，大厅界面由 Claude 实现。
